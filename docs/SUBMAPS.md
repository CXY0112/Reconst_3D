# rgbd 一阶段局部体素子地图

2026-10-21。`main.py rgbd` 的一阶段默认启用此后端，界面布局、二阶段算法和默认/iSAM2选择不变。普通main与Beta暂保留原全局体素后端，便于对照。

## 在线处理

原生RTAB-Map RGB-D视觉里程计、关键帧、回环及优化器不变。保留的关键帧仍保存RGB-D、标定、相机位姿、pointcloud_local局部预处理结果及map_frames帧级点云。

连续观测在局部坐标系中形成子地图，最多8个保留关键帧；相对锚点平移超过0.4m或旋转超过15度提前开启下一张。每张子地图内部保持3mm体素和观测权重。

历史位姿改变时，用各帧局部相对位姿及点位移上界检查一致性：

- 整组变化近似为共同刚体变换：只更新子地图锚点，不重新装载、撤销或逐帧融合内部点云。
- 内部相对变化超过0.75mm容忍尺度：仅重建相关子地图。每次实时更新最多重建一张历史子地图，新观测优先，旧任务公平推进。
- 连续修正直接以最新位姿快照为目标；不会依次融合每个过期版本。处理期间出现更新，不会误清除新的待修正标记。
- 未达到阈值的变化与上次实际融合结果比较，后续可以累积触发更新。

局部点云采用NumPy向量化体素聚合，替代每点Python/SQLite行写入。局部缓存上限64MiB，其余子地图按需从NPZ读取；这不是进程总内存上限。实时拼接后再次做全局3mm体素去重，避免子地图重叠区域直接堆叠。

## 最终输出与兼容

在线预览包含子地图局部量化和容忍尺度近似。点击完成时，使用最新每帧位姿及原map_frames质心重新进行全局融合，不使用子地图质心代替帧级观测。采用分层向量化合并，维持原3mm全局体素规则；最终保存的点云可与原全局后端逐项比较。

setp1保留原RGB-D、sdk_calibration.json、hp60c.yaml、geometry_poses.json、frames.jsonl、registrations.jsonl、pointcloud_local和map_frames。新增submaps/manifest.json及各子地图缓存文件。此模式不生成旧的voxel_map.sqlite；该SQLite不是二阶段的必需输入。full_geometry_world.npy、map_cloud.ply、map_poses.txt与原数据接口一致。二阶段继续从原观测及最终位姿读取，不从近似预览读取。

收尾需要一次精确全局融合，在线节省的时间不代表保存没有额外开销；相关对照必须同时报告在线与收尾时间。

## 本版边界

- 仍会将变化后的子地图组合为完整显示数组；尚未实现空间块GPU缓冲更新。
- rgbd全场景RGB着色仍采用已有可见性投影，并未改成增量着色。
- 关键帧局部清洗、表面估计和图像保存保持原实现。
- 不增加原生回环能力、跨会话续建能力或固定总内存保证。
- 目前仅验证已有观测回放和模拟相机；真实长序列收益需另行测量。

验证入口：`python Reconst_3D/tools/validate_submaps.py --output <新实验目录>`。对比修改前归档的后端与当前子地图后端，输入帧和目标位姿完全相同，不将前端接受帧差异混入稠密更新比较。结果位于results/experiments/submaps_20261021。

## Windows位姿快照修复

实拍发现建图线程替换geometry_poses.json时，着色线程同时读取会触发WinError 5。当前采用共享删除读取、同文件短读写临界区及ReplaceFileW替换现有目标；仅设置共享读取标志不足以解决Path.replace/MoveFileExW对打开目标的限制。

遇到短暂共享冲突时，在线检查点保留最新完整临时文件并暂缓提交，后续更新合并旧版本；不截断已提交JSON，也不因一次占用终止跟踪。结束时最多等待2秒确认提交；持续权限/占用异常仍明确报错并保留恢复数据，不把未提交位姿当成保存成功。子地图manifest采用同样机制。

已验证目标被占用、并发读写、旧快照读取、新位姿补写、持续占用失败保护，以及默认/iSAM2原生模拟采集叠加着色与外部锁。详见results/experiments/pose_sharing_fix_20261021/REPORT.md。需要关闭旧工作台进程并重新启动，已运行的Python进程不会自动载入修改。
