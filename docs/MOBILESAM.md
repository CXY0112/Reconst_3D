# RGB-D 第四阶段：框选提示分割

启动 `python Reconst_3D/main.py`，完成第三阶段彩色重建后进入第四阶段。仅提供提示分割，不自动扫描照片、不生成自动候选；Beta 同样保留本页。整体流程见 [彩色场景工作流](SCENE_WORKFLOW.md)。

1. 左侧查看完整场景，右上选择原始 RGB 照片，右下查看选中实例或框选预览点云。左右点云视角同步。
2. 在能看清目标的 RGB 照片上拖出矩形框。MobileSAM 只在此时运行，先预览掩码和深度一致的三维点，尚不改实例标签。
3. 选择修改方式，再点击“应用框选结果”：
   - 单独分出物体：将框选点整理为一个新实例，支持从旧实例中拆分。
   - 补入选中物体：先选一个已有实例，将另一视角的可见表面补入同一物体。
   - 从选中物体移除：只移除该实例与当前掩码重合的点，其余实例不受影响。
4. 支持列表多选合并、撤销、导出选中物体彩色 PLY。“清空分割”仅重置内存中的实例标签，支持撤销；保存后才覆盖已有分割记录。
5. “保存 / 覆盖本阶段”写入数据集的 `rgbd_scene/setp4/segmentation`。旧版自动分割结果仍可恢复和继续框选编辑；也可清空后重新手动划分。

## 数据与边界

- 不需要目标名称，不预测语义类别。提示框应主要包含一个目标，应用前检查预览。
- 只修改可见、与同像素 SDK 深度相差不超过 30 mm 的点；掩码边缘内缩 2 px。框选不会自动补齐背面，应换照片后“补入选中物体”。
- 原始点坐标、RGB、深度、内参和位姿保持不变。未分配点保留为灰色；可切换“原始 RGB”查看完整彩色场景。
- 撤销最多保留 12 次，索引快照约 64 MiB 预算；较大修改会提前释放更早记录。
- `labels.npz` 引用原点索引，`report.json` 保存框选记录、来源指纹。保存/恢复时检查依赖观测，原始 RGB-D 或位姿改变后拒绝混用旧标签。
- 迁移时保留整个数据集的 setp1、rgbd_scene/setp2 和 rgbd_scene/setp4。只导入独立点云而没有关联 RGB-D/位姿时无法使用照片框选。

## 模型环境与性能

模型只在首次框选时加载，最多缓存两张照片的编码；关闭窗口或取消推理时回收进程。本机 CPU 实测，同照片第一次框选模型处理约 1.1 s，缓存命中后约 0.08–0.09 s；端到端仍需加上进程首次启动、来源校验、三维投影和界面更新时间。

本机使用独立 WSL CPU 模型环境，由 `vendor/mobilesam/runtime.json` 指向解释器；其他电脑可以直接使用原生 Windows / Linux 的模型环境，不要求 WSL。

1. 在独立模型环境安装匹配的 `torch`、`torchvision`，以及 `timm`、`pillow`、`numpy`。
2. 运行 `python Reconst_3D/tools/setup_mobilesam.py` 获取并校验固定的官方源码和权重。
3. 将 `RECONST_MOBILESAM_PYTHON` 设置为模型环境 Python 的绝对路径，再启动工作台；Linux 也可直接用已安装模型依赖的 Python 启动。
4. 推理优先使用可用 CUDA，否则 CPU。Windows CUDA、Linux CUDA、Jetson 性能尚未在本机验证。
